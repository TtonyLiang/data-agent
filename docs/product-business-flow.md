## 2. 当前业务方向

问渠 WenQu 当前定位为：

> **Ontology 驱动的企业运营数字孪生与智能决策平台。平台将企业业务理解和数据组织为 AI 可消费的统一业务模型与标准能力，作为企业智能中枢和决策引擎。**

平台目标不是把所有业务都放进一个聊天窗口，而是先建设可被不同 Agent 和应用复用的企业级底座：

```text
数据库 / API / 文件 / 业务事件
-> 企业模型中心
-> 数据处理与孪生运行时
-> Query / Decision / Action Capability
-> 财税 Agent / 贷款 Agent / 其他业务应用
-> 结果反馈与决策审计
```

财税报告交付、贷款风控、智能问数是平台上的垂直应用与验证场景。当前以贷款合成数据验证技术闭环；其规则、阈值和结论不是已经验证的财税、审计、合规或授信规则。

当前阶段的第一目标是把三块基础能力做扎实：

1. **企业模型中心**：统一业务对象、关系、指标、规则、映射、状态、动作、权限和版本。
2. **数据处理与孪生运行时**：把源数据转换为有身份、有状态、有来源的业务对象。
3. **能力发布中心**：把模型和数据转成 Agent 可稳定调用的查询、决策和动作能力。

Agent 是这些企业资产和能力的消费者。对话功能当前只需完成能力演示、接口验证和必要的人机交互，不是近期建设重心。

## 3. 功能块如何联动

| 功能块 | 主要职责 | 与其他模块的关系 |
|---|---|---|
| 企业空间与业务领域 | 定义企业资产归属、安全边界和可独立发布的业务范围 | 领域持有模型、数据映射、版本和能力；Agent/应用按授权消费领域 |
| 企业模型中心 | 统一管理原“查询语义”和“本体建模”资产 | 对象语义回答“业务里有什么”，指标与映射回答“数据在哪里、怎么算”，状态与动作回答“现在怎样、可以做什么” |
| 数据源与孪生运行时 | 连接业务数据，映射、同步并查询对象实例 | 为企业模型提供真实状态；P0 复用现有触发式同步，生产级增量同步和身份解析后续建设 |
| 能力发布中心 | 发现和调用 Query / Decision / Action Capability | 把模型、数据、规则和动作包装成 Agent/应用稳定接口；P0 先聚合现有能力 |
| Agent 与对话 | 绑定模型并消费已授权领域能力，完成场景交互 | 是平台能力的消费者和演示入口，不再拥有领域与本体资产 |
| 风险交付 | 管理风险事项、证据、人工复核、报告版本和审计 | 是财税/贷款垂直验证场景，用于证明模型、数据、能力和决策审计可以形成闭环 |
| 模型配置 / Prompt / 系统参数 | 管理模型、提示词、召回阈值和运行参数 | 支撑理解与生成，但不替代企业模型、规则和权限 |
| 用户与权限 | 管理成员、角色、Agent 授权和数据访问边界 | 共同约束领域、数据源、表、列和能力调用 |

### 3.1 为什么需要“企业空间与业务领域”

这不是为了增加管理层级，而是为了解决“本体资产到底属于谁、如何复用、如何隔离”的问题。

- **企业空间**是企业资产与安全边界。它回答：这套模型、数据连接和能力属于哪家企业，谁可以管理和审计。
- **业务领域**是可独立梳理、发布和复用的业务范围。它回答：这是客户、财税、授信还是风险管理模型，由谁负责，使用哪些数据源。
- **Agent**是使用方。它回答：某个垂直场景需要调用哪些已发布领域和能力，用什么模型与用户交互。

目标业务关系为：

```text
企业空间
  -> 业务领域
      -> 企业模型 / 数据映射 / 发布版本 / 能力
          -> 多个 Agent 与应用按授权消费
```

因此，同一“客户”领域不需要为财税 Agent、客服 Agent 和风控 Agent 重复建三遍；一个 Agent 也可以组合多个已授权领域。领域下线或更换 Agent 时，企业模型仍作为企业资产保留。

P0 保持克制：单企业演示环境自动使用默认企业空间，旧数据兼容归入默认空间和领域，并增加 Agent-领域多对多绑定。生产级多租户隔离、组织树、领域负责人审批和跨领域依赖治理后续再做。

### 3.2 企业模型中心：统一查询语义与 Ontology

两者不是两套互相独立的产品，而是同一个企业业务模型的两类资产：

- **查询语义负责聚合分析**：指标是什么、维度是什么、映射到哪张表哪个字段、如何 JOIN、如何生成 SQL。
- **Ontology 负责业务对象与动作**：客户、申请、账户、风险快照等对象当前是什么状态，可以执行什么动作，动作会怎样改变状态。

产品上统一为“企业模型中心”，共同使用企业空间、业务领域、稳定 `object_key` 和发布版本。底层表和运行服务可分阶段兼容，不要求本轮大规模重写。查询时，查询语义指导 LogicForm 和 SQL，Ontology 对象、关系和动作证据参与业务理解及 Schema 打分。

#### 对象、事件、状态和动作的边界

Ontology 中的“对象”不只指客户、账户这类物理实体，也可以是有业务身份和生命周期的申请单、订单、交易或案件。建模时应区分四层：

| 层次 | 用途 | 贷款示例 |
|---|---|---|
| 对象 | 可独立识别、可查询、可关联的业务实体或业务记录 | 贷款申请单、贷款账户、催收案件 |
| 事件 | 记录某个时间点发生的业务事实 | 提交申请、审批通过、放款 |
| 状态 | 表示对象当前处于哪个阶段 | 待审核、已通过、逾期 |
| 动作 | 对对象执行的受控业务操作 | 审批申请、发起催收、结案 |

“贷款审批流程”是流程规则，不应直接命名为 `LoanApplication`；`LoanApplication` 应明确表示“一笔申请单”。如果需要记录每次审核的人员、时长、意见和状态变化，可以增加 `ApprovalReview` 或状态变化事件/历史对象。

### 3.3 数据处理与孪生运行时

运行时负责把“数据库里的行”转换为“业务里的对象”：

```text
源数据 -> 字段映射 -> 对象身份 -> 当前状态 -> 关系 -> 来源与更新时间
```

当前已经有业务库只读对象同步、对象实例查询，以及 `source_properties + overlay_properties` 的状态合并。P0 新增统一的“孪生运行”可见入口，但仍由页面或 API 触发同步，不是后台定时任务或 CDC。

后续重点是定时/增量同步、跨系统同一对象识别、状态变化历史、数据质量、冲突处理、血缘和运行监控。

### 3.4 能力发布中心与 Agent

能力中心把内部实现转换为外部 Agent 可依赖的稳定契约：

- `Query Capability`：只读对象查询、过滤、关联、聚合和指标计算。
- `Decision Capability`：基于规则或模型形成判断、原因和建议，后续建设。
- `Action Capability`：创建、修改、审批、状态变化或外部写回等受控操作。

当前已有对象查询、第一版 Query Capability 和 Action 工具。P0 将其集中展示和调用；正式发布版本、输入输出 Schema 治理、灰度、限流、配额、依赖分析和生产级调用网关仍属于后续。

### 3.5 风险交付是垂直验证场景

风险交付把对话和 Ontology 连接成完整业务流程：

- 从对话结果创建风险事项时，系统按 `agent_id + session_id + trace_id` 精确找到问数轮次。
- 自动冻结问题、LogicForm、SQL、结果预览、分析产物等查询证据。
- 用户可选一个 Ontology 对象，额外冻结该对象的状态快照。
- 产品流程上，风险事项应经过指派复核后再进入报告版本。
- Ontology 动作、风险事项、证据、复核和报告版本共同写入决策审计链。

## 4. 管理员配置流程

目标配置顺序从“先创建 Agent”调整为“先沉淀企业资产，再授权给 Agent”：

1. **进入企业空间并选择业务领域**
   - 单企业 P0 默认进入系统创建的默认企业空间。
   - 新建或选择一个可独立负责、发布和验收的业务领域。
2. **连接并治理数据源**
   - 添加业务数据库连接并测试。
   - 读取远端表清单，只采集需要参与业务的表。
3. **在企业模型中心梳理业务**
   - 定义对象、属性、关系、事件、状态和动作。
   - 配置概念、指标、规则、关系、字段映射和 LogicForm 模板。
   - 通过稳定 `object_key` 串联业务对象、查询口径和数据映射。
4. **校验并发布企业模型**
   - 校验主键、字段映射、关系、指标和动作引用。
   - 发布领域版本；P0 沿用现有 Ontology release 和语义资产兼容机制。
5. **运行数据孪生**
   - 配置并触发现有对象只读同步，检查实例数量、状态和来源。
   - 生产级定时增量同步、身份冲突和坏数据报告后续补齐。
6. **检查并发布业务能力**
   - 在能力发布中心核对可用的对象查询、Query Capability 和 Action Capability。
   - P0 是能力聚合入口，不等同于正式生产发布网关。
7. **创建或配置 Agent**
   - 绑定大语言模型、向量模型和一个或多个已授权业务领域。
   - 配置推荐问题；对话只用于验证该 Agent 能否正确消费平台能力。
8. **配置用户与数据权限**
   - 创建或启用用户。
   - 为普通用户分配可访问智能体。
   - 按需要维护领域/Agent、数据源、表级和列级边界。
9. **按需调整运行配置**
   - 修改 Schema 召回阈值、候选表数量或节点 Prompt。
10. **进入垂直场景验证**
    - 组织问数、风险事项、复核、报告版本、受控动作和审计回放。

兼容说明：`semantic_domain.workspace_id` 表示企业空间归属，`agent_semantic_domain` 表示 Agent-领域多对多关系；`semantic_domain.agent_id` 和 `agent.semantic_domain_id` 继续保留为历史归属与默认领域兼容字段。删除 Agent 只解除绑定并清理 Agent 自身运行数据，不删除业务领域、Ontology、风险或决策资产。表级白名单和列级脱敏运行时已经实现，但当前前端还没有完整维护入口。

## 5. 普通用户产品流程

### 5.1 登录与选择智能体

- 注册用户默认是启用状态的普通用户。
- 新用户没有智能体权限时无法开展问数，需要管理员授权。
- 普通用户只能看到已授权智能体，以及这些智能体对应的领域。
- 普通用户可以从企业模型、孪生运行和能力中心查看有权限领域的模型、对象状态与可用能力，但不能修改模型定义。

### 5.2 日常问数

1. 选择智能体或使用管理员配置的默认智能体。
2. 用自然语言提出业务问题。
3. 查看系统的语义增强、语义资产、Ontology 命中、候选表字段和查询过程。
4. 查看最终答案、SQL、结果表；明确要求分析、趋势、报告或图表时进入深度分析。
5. 在同一会话中继续追问、修改时间/维度、重新执行或分析上一轮结果。

### 5.3 从问数进入风险交付

1. 在已完成的查询结果上点击“创建风险事项”。
2. 确认风险标题、分类、严重度、指派复核人和可选 Ontology 对象。
3. 系统自动固化查询证据和分析证据，不需要手工复制 SQL 与结果。
4. 进入风险交付工作台补充证据或查看完整证据链。
5. 被指派的其他用户执行复核；普通用户不能复核自己创建的事项。
6. 创建草稿报告及 V1，后续修订必须创建新版本。
7. 管理员完成最终定稿。

### 5.4 Ontology 业务操作

- 普通用户可以查看自己有领域权限的对象、关系、动作和发布版本。
- 普通用户可以触发业务库只读同步，并查看对象实例。
- 只有满足动作 `allowed_roles`、状态、发布版本、参数、前置条件、审批单号和对象版本校验时才能执行动作。
- 普通用户只能查看自己的动作执行记录，管理员可以查看全部记录。

## 6. 智能问数运行流程

当前问数不是简单的“问题直接交给模型生成 SQL”，而是受控的持久任务循环：

```text
加载 checkpoint
-> 判断本轮是新问题、追问、重试还是继续分析
-> 每次只选择一个白名单动作执行
-> 保存 observation 和 checkpoint
-> 完成、等待补充或进入下一动作
```

一次新的数据问题通常按以下链路推进：

1. **意图识别**：区分数据查询、闲聊和元数据问题。
2. **语义增强**：结合当前问题、历史问题和领域 rewrite 规则补全指标、维度、时间及 TopN。
3. **语义与 Ontology 召回**：加载当前智能体的指标、概念、规则、映射和模板，同时加载当前领域中 active 的对象、关系和按角色可见的动作定义，并携带最新 release 信息。
4. **Schema 定位**：只在已绑定数据源、已采集 Schema 和智能体权限范围内，对表、字段和 JOIN 关系打分。
5. **LogicForm 生成**：把问题转换为指标、维度、过滤、时间、排序和限制等结构化意图。
6. **语义校验**：检查 LogicForm 是否引用了合法资产及可用维度。
7. **确定性 SQL 编译**：命中语义层时由代码编译 SQL；语义层不足或编译失败时才进入受限 NL2SQL 兜底。
8. **SQL 安全与权限校验**：限制为单条只读 SELECT，检查表权限，强制结果上限。
9. **业务库执行与脱敏**：执行查询，并按列级策略对结果做隐藏或脱敏。
10. **回答或深度分析**：简单问题直接整理答案；分析类问题继续进入 Python 安全执行、图表和 Markdown 报告。
11. **持久化**：查询过程、LogicForm、SQL、结果、报告写入 `chat_history`；可续跑状态写入 `agent_task_checkpoint`。

### 6.1 系统如何识别相关表和字段

表和字段不是只靠大模型猜测，而是多种信号共同打分：

- 用户原问题和语义增强后的关键词。
- 语义指标、概念、规则和映射中的名称、描述与同义词。
- Ontology 对象、属性、关系和动作命中结果。
- 已采集表名、表注释、字段名、字段注释和外键。
- 领域配置的 recall profile、schema hint 和业务分组。
- 系统参数中的相对分数阈值和最大候选表数。

最终只有通过用户、智能体、数据源、表和列权限筛选后的 Schema 才会进入 LogicForm、SQL 兜底上下文和查询执行。

## 7. 数据如何串联

### 7.1 三类存储

| 存储 | 保存内容 | 写入边界 |
|---|---|---|
| 业务数据库 | 客户、申请、账户、财税凭证等真实业务数据 | 问数和 Ontology 同步只读；当前 Ontology 动作不直接更新业务库 |
| 管理数据库 | 用户、智能体、模型、数据源、Schema、语义资产、Ontology、会话、风险、报告和审计 | 平台配置和业务工作流的主要落库位置 |
| 向量存储 | 语义资产 embedding | 用于语义召回；失败时可降级为关键词召回 |

### 7.2 关键关联标识

| 标识 | 串联范围 |
|---|---|
| `user_id` | 用户身份、会话归属、任务、动作、复核和审计 |
| `workspace_id` | 企业资产、安全和治理的顶层归属；P0 单企业环境使用默认空间 |
| `agent_id` | Agent 配置、用户授权和当前问数兼容运行边界；不再表示领域资产所有者 |
| `datasource_id` | 物理数据库、已采集 Schema、表列权限和 SQL 执行 |
| `domain_id` | 企业模型、数据映射、Ontology、能力、风险事项、报告和审计的业务领域 |
| `session_id` | 一段多轮对话 |
| `trace_id` | 一次问数结果与风险证据的精确血缘 |
| `task_id / turn_id` | 持久任务与某次用户轮次 |
| `ontology_release_id` | 风险、证据、报告版本和动作所依据的业务模型版本 |
| `subject_object_id` | 风险事项关联的 Ontology 对象 |

### 7.3 核心数据链路

```text
datasource
-> meta_table / meta_column
-> semantic_mapping / semantic_metric / semantic_relation
-> LogicForm
-> compiled_sql
-> business database result
-> chat_history + trace_id
-> risk_issue
-> risk_evidence + risk_issue_review
-> risk_report + risk_report_version
-> decision_audit_event / decision_audit_head
```

Ontology 对象同步采用两层属性：

```text
展示和动作校验属性 = source_properties + overlay_properties
```

- `source_properties` 来自业务库只读同步。
- `overlay_properties` 来自 Ontology 动作的本地状态变更。
- 同名字段以 overlay 为准，因此刷新业务库不会覆盖已执行动作的本地结果。

## 8. 权限边界

### 8.1 页面与配置权限

| 能力 | 普通用户 | 管理员 |
|---|---:|---:|
| 对话 | 已授权智能体 | 全部智能体 |
| 风险交付 | 可访问领域内使用 | 可访问全部领域并定稿报告 |
| 企业模型 | 查看有权限领域的 Ontology | 配置查询语义与 Ontology，导入、校验、发布 |
| 孪生运行 | 查看并触发现有对象同步 | 查看并触发现有对象同步 |
| 能力发布中心 | 查看能力；按角色调用 | 查看全部能力；按角色调用 |
| Ontology 动作执行 | 按 `allowed_roles` | 按 `allowed_roles` |
| 智能体、模型、数据源 | 不可以 | 可以 |
| Prompt、系统参数、用户管理 | 不可以 | 可以 |

### 8.2 数据访问边界

当前兼容链路的数据访问依次经过：

```text
用户是否可访问智能体
-> 智能体是否绑定数据源
-> 表是否在允许范围
-> 列是否允许或需要脱敏
-> SQL 是否为安全只读查询
```

当前精确规则：

- 没有表权限配置时，智能体默认可以访问已绑定数据源中的已采集表。
- 一旦该智能体/数据源存在表权限记录，未列出的表默认拒绝。
- 未配置列权限时默认允许且不脱敏。
- 列脱敏支持 `redact`、`partial` 和 `hash`。
- SQL 执行前会再次检查表权限，结果返回前再次应用列脱敏。

目标权限链路在此基础上增加“企业空间成员 -> 业务领域授权 -> Agent/应用能力授权”。P0 不重写现有权限引擎，先保持兼容并明确资产归属；后续再形成独立于对话 Agent 的领域和能力授权。

### 8.3 风险与报告权限

- 普通用户只能把自己的对话结果转换为风险事项；管理员可跨用户做技术验收。
- 普通用户不能复核自己创建的风险事项，并且必须是该事项的指派复核人。
- 普通用户可以创建风险事项、补充证据、创建草稿报告和新版本。
- 报告定稿仅管理员可执行；定稿后不能继续创建新版本。

## 9. 当前实现边界

截至 2026-09-03，P0 增加的是兼容骨架和统一产品入口：默认企业空间与领域归属、Agent-领域多对多、企业模型入口、孪生运行页和能力发布中心页。孪生运行页复用现有触发式同步 API；能力中心复用现有对象查询、Query Capability 和 Action 工具。

以下能力当前没有实现，文档和演示中不能当作已有能力：

- 对话 ReAct 尚未自动调用 Ontology 动作；动作主要从本体工作台或受控 REST 工具执行。
- Ontology 同步是进入对象实例页、切换类型、翻页或点击刷新时触发，不是 CDC 或后台定时任务。
- Ontology 动作当前只更新管理库对象和 overlay，不直接写回 ERP、催收、短信或业务数据库。
- `requires_approval` 当前表示执行时必须提供审批单号，不是完整审批流。
- 尚未实现动态 ABAC、生产级动作幂等与失败补偿、分布式图事务。
- 表/列权限运行时已存在，但前端尚无完整维护界面。
- 当前列权限主要控制 Schema 可见性和结果脱敏，SQL 执行前只做表级引用检查，尚未实现完整 SQL 字段级拦截。
- 当前报告创建接口尚未强制要求所绑定风险事项已经复核或确认，复核后出报告目前属于产品流程约束。
- 贷款数据和规则只用于技术演示，不能作为真实业务判断依据。
- 企业空间尚不是完整多租户组织系统，领域治理尚未包含正式负责人审批和跨领域依赖管理。
- 能力发布中心尚不是生产级网关，未包含完整的版本订阅、灰度、限流、配额、SLA 和依赖影响分析。
- 通用 Decision Capability、预测模型治理和预测结果反馈闭环尚未形成。

## 10. 已确认的开发计划

这里汇总平台主线和垂直场景验证线。详细工程排期见 [Ontology 产品路线图](./ontology-product-roadmap.md)。

### 10.1 平台建设主线

| 阶段 | 当前状态 | 目标 |
|---|---|---|
| P0 兼容骨架 | 第一版已实现 | 默认企业空间、领域归属、Agent 多对多消费和三个统一产品入口 |
| P1 企业模型中心 | 下一重点 | 统一建模、映射测试、领域发布、版本差异、回滚和影响分析 |
| P2 孪生运行时 | 下一重点 | 定时/增量同步、身份解析、状态历史、数据质量、血缘和运行监控 |
| P3 能力发布中心 | 下一重点 | Query / Decision / Action 的正式契约、版本、权限、审计和运行治理 |
| P4 垂直场景验证 | 持续并行 | 用财税、贷款等真实场景验证准确率、效率、可解释性和决策价值 |

近期执行原则：

1. 先把企业模型、数据运行时和能力发布中心做成清晰、稳定、可验证的底座。
2. 保持现有问数可用，只做必要的能力消费演示，不把复杂对话优化作为主线。
3. 用既有贷款切片做回归，再选择一个真实业务领域验证模型和数据映射。
4. 未完成真实数据、规则和人工边界验证前，不宣称平台已能自动替代业务决策。

### 10.2 垂直场景验证线

| 阶段 | 当前状态 | 目标 |

| A. 贷款技术切片 | 技术实现完成 | 用合成案例回归风险、证据、复核、报告、动作和审计契约 |
| B. 真实领域选择 | 未开始 | 确认业务负责人、核心对象、数据来源、指标、规则和能力清单 |
| C. 历史案例影子运行 | 未开始 | 与现有人工流程并行，量化结果差异、时间节省和可追溯性 |
