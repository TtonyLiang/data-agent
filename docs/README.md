# 问渠 WenQu 文档目录

> 最后核对：2026-09-09

本目录当前统一服务于 **公司内部使用的 Ontology 驱动企业运营数字孪生与智能决策平台**。平台先沉淀业务理解和数据，再通过能力接口供本项目验证 Agent 以及外部第三方 Agent/业务应用使用。财税、贷款和智能问数只是验证场景，不是平台边界。

> **第一性目标：让业务语义成为企业资产，让数据库成为数据来源，让 Agent 成为能力消费者。**

## 功能块地图

```text
公司内部治理与权限
  → 业务领域
  → 企业模型中心（Ontology + 查询语义）
  → 数据处理与孪生运行时
  → 能力发布中心（标准 API；SDK 后续建设）
  → 外部 Agent / 业务应用
```

本项目内的 Agent/对话页只是调试和验收客户端，用来验证“外部 Agent 调用同一能力时也能得到同样效果”。截至 2026-09-09，下一阶段五个功能块已完成第一轮代码建设，但尚未完成真实业务与生产数据验收：

| 功能块 | 当前已实现 | 仍需完成 |
|---|---|---|
| 真实数据接入安全门槛 | 表白名单默认拒绝；列权限、别名血缘和结果脱敏；对象、关系、Action 与同步共用权限主体 | 在真实测试库验证允许、拒绝和脱敏结果 |
| 企业模型中心产品化 | 已按“业务模型 → 数据绑定 → 校验发布”重排；指标和规则按对象组织；表字段优先从 Schema 选择；对象映射向导、统一版本与安全编辑已落地 | 真实领域建模验收、版本 diff、影响分析和完整回滚闭环 |
| 孪生运行时第一版 | 手动预览/执行、分页同步、对象/关系实例、动作执行记录和运行统计；强制绑定激活模型并校验数据源/定义漂移 | 增量调度、CDC、身份合并和状态历史 |
| 能力发布与 Agent 解耦 | 第三方调用凭据、Query 授权、标准调用 API、错误脱敏和调用审计 | SDK、Decision/Action 外部调用、限流和灰度治理 |
| 业务验收与回归 | 已建立内置调用与外部调用的一致性自动化基线 | 5–10 条真实业务问题、结果基线和业务签字验收 |

“第一轮代码建设”不代表相关产品阶段已经完成。是否可接入生产敏感数据，仍以路线图中的真实领域前置条件为准。

## 术语统一

- `Domain` 统一称 **业务领域**；它是公司内部模型、数据映射和能力的管理边界，不是租户边界。
- **企业模型** = Ontology 对象/关系/状态/动作 + 查询语义概念/指标/规则/映射/模板。
- **Agent** 是企业模型和能力的消费者；本项目里的 Agent 主要用于调试/验证，第三方 Agent 不需要先在本项目创建 Agent。
- **企业空间**不是产品概念；代码中的 `enterprise_workspace/workspace_id` 仅是单公司部署的内部兼容容器。
- **风险交付** 是贷款/财税技术切片，不是平台通用能力的唯一入口。
