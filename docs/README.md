# 问渠 WenQu 文档目录

> 最后核对：2026-09-04

本目录当前统一服务于 **公司内部使用的 Ontology 驱动企业运营数字孪生与智能决策平台**。平台先沉淀业务理解和数据，再通过能力接口供本项目验证 Agent 以及外部第三方 Agent/业务应用使用。财税、贷款和智能问数只是验证场景，不是平台边界。

## 功能块地图

```text
公司内部治理与权限
  → 业务领域
  → 企业模型中心（Ontology + 查询语义）
  → 数据处理与孪生运行时
  → 能力发布中心（API / SDK）
  → 外部 Agent / 业务应用
```

本项目内的 Agent/对话页只是调试和验收客户端，用来验证“外部 Agent 调用同一能力时也能得到同样效果”。当前 P0 有统一入口和兼容骨架；正式能力网关、SDK、持续同步和调用治理仍在路线图中。

## 术语统一

- `Domain` 统一称 **业务领域**；它是公司内部模型、数据映射和能力的管理边界，不是租户边界。
- **企业模型** = Ontology 对象/关系/状态/动作 + 查询语义概念/指标/规则/映射/模板。
- **Agent** 是企业模型和能力的消费者；本项目里的 Agent 主要用于调试/验证，第三方 Agent 不需要先在本项目创建 Agent。
- **企业空间**不是产品概念；代码中的 `enterprise_workspace/workspace_id` 仅是单公司部署的内部兼容容器。
- **风险交付** 是贷款/财税技术切片，不是平台通用能力的唯一入口。

### 维护约定

- 每次迭代完成或方向调整时，先更新 `ontology-product-roadmap.md` 的阶段状态、验收口径和迭代记录。
- 业务流程、技术设计或专题路线发生变化时，再同步更新对应文档；不要在多个文件里各自维护进度数字。
- 新增真实业务领域前，先完成 `business-data-onboarding.md` 中的领域卡、表清单、权限清单和验收问题集。
- 新增或完成一项能力时，同时写清“当前状态”和“明确不包含”，避免把规划写成现状。
- 已废弃或仅保留历史依据的内容移入 `docs/archive/`，不要继续放在当前核心文档列表中。
- `docs/todo/`、临时设计稿和个人会议记录不作为项目验收依据。
