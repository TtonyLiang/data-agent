# 问渠 WenQu 文档入口

> 最后核对：2026-09-15

问渠是公司内部使用的 **Ontology 驱动企业运营数字孪生与智能决策平台**。

> **第一性目标：让业务语义成为企业资产，让数据库成为数据来源，让 Agent 成为能力消费者。**

## 3. 平台主链路

```text
公司内部治理与权限
  → 业务领域
  → 企业模型（Ontology + 查询语义）
  → 数据映射与孪生运行时
  → Query / Decision / Action 能力发布
  → 第三方 Agent / 业务应用
     （内置验证智能体只作验收，不是正式接入方式）
```

当前重心是企业模型、数据运行时和能力发布。内置验证智能体/对话只用于验收平台能力是否达标；验收标准是第三方 Agent 调用同一合同得到同样业务结果。风险交付、贷款和财税属于垂直验证场景。

## 5. 统一术语

- 平台产品角色只有 **业务人员** 和 **技术人员**；首次说明时写“技术人员（包含数据库工程师）”。
- `admin/user` 是历史兼容账号值，不是额外角色；当前开发验证由项目开发者使用 `admin` 贯穿操作。
- `Domain` 统一称 **业务领域**，是公司内部模型、数据映射和能力的管理边界，不是租户边界。
- **企业模型**统一包含 Ontology 对象/关系/状态/动作与查询语义指标/规则/映射/模板。
- **内置验证智能体**只用于验收平台能力是否达标，不拥有企业模型，也不代表第三方运行形态。
- **第三方 Agent** 通过能力发布中心调用同一合同，应得到同样的业务结果。
- **企业空间**不是产品概念；兼容代码中的 workspace 只作为单公司内部容器。
- **风险交付**是垂直验证场景，不是平台的通用主入口。

## 6. 维护规则

- 路线、阶段、优先级和验收记录只写入 `ontology-product-roadmap.md`。
- 业务流程、技术实现、项目结构和接入 SOP 各写各的，不复制整段内容和进度数字。
- “当前已实现”必须有页面、API、测试或手工验收依据；否则写“已有基础”“计划中”或“明确不包含”。
- 一次性审计、完成后的整改清单和过期调研移入 `archive/`。
- 特定业务场景放入 `scenarios/`；稳定技术说明放入 `reference/`。
- 新增真实领域前，先完成接入手册中的范围、表、权限、主键、指标和验收问题确认。
- 根目录 `AGENTS.md` 约束项目开发与文档维护，但不能成为第二份产品路线图。
